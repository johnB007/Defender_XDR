MDE Linux Live Response Troubleshooting Field Guide

Purpose: Self-contained onsite guidance for investigating MDE on Linux through Microsoft Defender Live Response.

Applies to: Supported Linux devices onboarded to MDE, including DoD IL5 / US Government.

Validated: September 28, 2026. Use help <command> to confirm syntax exposed by the current service.

Important: Live Response is not a normal Bash prompt. Enter only Live Response commands in the console. Run Linux commands through an uploaded Bash script with run.

1. Before going onsite

  • Confirm the device is in the Defender device inventory.
  • Linux Live Response requires MDE agent version 101.45.13 or later.
  • Enable Live Response and Live Response for servers.
  • Confirm RBAC access to basic and advanced commands.
  • Upload both Bash scripts to the tenant library before travel.
  • US Government library size is 5 MB by default.

2. Onsite workflow

Connect and verify the library

connect
help
library

Run connectivity analysis first

run LinuxMDEConnectivityAnalyzer-IL5.sh
getfile "/tmp/IL5MDEConnectivity_<device>_<UTC>.tar.gz"

Open IL5-MDE-Connectivity-Report.html after extracting the archive.

On Windows 10 or 11, open PowerShell in the download folder:

$archive = ".\IL5MDEConnectivity_<device>_<UTC>.tar.gz"
$folder = ".\IL5MDEConnectivity_<device>_<UTC>"
New-Item -ItemType Directory -Path $folder -Force | Out-Null
tar -xzf $archive -C $folder
Start-Process "$folder\IL5-MDE-Connectivity-Report.html"

Interpret key results

ResultMeaning
PASSRequired network and MDE checks succeeded.
HTTP 4xx and PASS: REACHABLEThe anonymous request was rejected, but DNS, TCP, TLS, and HTTP transport worked.
HTTP 5xx and WARN: REACHABLEThe service or gateway responded. Check the native MDE test; this is not a firewall failure by itself.
HTTP 000 or curl failureInvestigate firewall, proxy, routing, timeout, TLS, or certificate validation.
HTTP 407Proxy authentication is required.
DNS unresolvedInvestigate the configured resolver and DNS policy.
TCP failureInvestigate route, firewall, proxy design, and endpoint allowlist.
TLS verify not 0Investigate time, trust store, and TLS inspection.

Run full diagnostics when needed

run Collect-MDELinuxDiagnostics.sh
getfile "/tmp/MDELinuxDiagnostics_<device>_<UTC>.tar.gz"

Open MDE-Linux-Diagnostics-Report.html. Retain the raw evidence for approved escalation channels.

Clean up exact device archives

remediate file /tmp/IL5MDEConnectivity_<device>_<UTC>.tar.gz
remediate file /tmp/MDELinuxDiagnostics_<device>_<UTC>.tar.gz

remediate file permanently deletes the endpoint copy. It does not delete the analyst download.

4. Console techniques

# Current syntax
help run
help getfile
help remediate

# Background download
getfile "/tmp/large-report.tar.gz" &
jobs
status <command_ID>
fg <command_ID>

# Save output on device, then retrieve
processes > processes.txt
getfile processes.txt

JSON usually exposes more fields than table output. Ctrl+Z moves a waiting download to the background. Ctrl+C cancels the portal-side display and might not stop endpoint-side work.

5. Limits

  • 50 simultaneous sessions per tenant; five per user; one per device.
  • 30-minute inactivity timeout.
  • Most commands: 10 minutes. getfile, findfile, and run: 30 minutes.
  • getfile: 3 GB. fileinfo: 30 GB.
  • General library: 250 MB. US Government default: 5 MB.
  • putfile on non-Windows platforms: 10 MB.

6. Fast troubleshooting matrix

SymptomAction
Session will not connectCheck service, agent version, Live Response settings, RBAC, clock, proxy, and endpoints.
Device is spottyRun the IL5 analyzer and retain HTML, CSV, TLS, and native output.
Connectivity passes but MDE is unhealthyRun the full diagnostic collector.
Native MDE test failsInvestigate the exact hostname reported by mdatp.
Service inactiveCollect diagnostics before making service changes.

8. Escalation package

  1. Device and UTC investigation window.
  2. Distribution, version, architecture, and kernel.
  3. MDE version and organization ID.
  4. Exact symptom and reproduction time.
  5. Both retrieved archives.
  6. Firewall or proxy logs for failed destinations.
  7. TLS inspection status and recent environment changes.
